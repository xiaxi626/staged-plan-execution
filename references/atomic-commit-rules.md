# 原子提交规则（严格遵守）

> 此段内容在生成的 prompt 中作为"## 原子提交规则（严格遵守）"小节输出，且在交接 prompt 中作为"逐字复制段落"之一原样复制。

每个步骤拆成两个提交（若无文档改动则只需第一个）：

1. 先一个 `fix(scope):` 提交——包含代码改动、测试、重建的编译产物（若适用）、CHANGELOG 文字修订
2. 再一个 `docs:` 提交——只包含 README / 文档的改动

绝不把代码和文档混在同一个提交里。

## 编译产物适用范围补充说明

> 此补充说明在交接 prompt 中紧随"原子提交规则"之后输出，用于消除"项目风格要求"第 4 条与本规则第 1 条之间的执行冲突，不改变两段原文。

- 原子提交规则中的"重建的编译产物"仅在本步骤代码改动会使编译产物发生变化时才适用
- 若本步骤改动会影响编译产物：在该步 `fix` 提交前运行编译，并把编译产物纳入该步 `fix` 提交
- 若本步骤只改测试、CHANGELOG、README、补全脚本、help 文本等不会影响编译产物的内容，或改动后编译产物无差异：不强制重建/提交编译产物
- 最终步骤仍必须执行全量编译，并确认所有质量门禁通过
